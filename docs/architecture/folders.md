# 文件夹与标签的管理

[← 架构](../architecture.md)

新建、重命名、删除账户的文件夹（Gmail 上是标签）。代码在 `crates/catmail-core/src/folders.rs`，
门面是 `MailClient::create_folder` / `rename_folder` / `delete_folder`。

## 当场在服务器上做，不进操作队列

对邮件的改动先改本地、再经操作队列回放（见[操作队列](op-queue.md)）；文件夹的改动不这样做，而是
当场发 `CREATE` / `RENAME` / `DELETE`，连不上就失败，本地什么也不变：

- 只在本地的文件夹没有 UIDVALIDITY，移进去的邮件的 op 无从绑定（UID 只在某一代里有意义）。
- 名字被占用、服务器不允许的名字，只有服务器说了才知道；排进队列，用户就要在之后某个时刻收到一个
  "被拒绝"的通知，而那时可能已经往里面移了邮件。
- 主流客户端都这样做；文件夹的改动很少，需要在线是可以接受的代价。

每个操作都在连接池的连接上、持有账户的同步锁执行（与同步、回放串行），做完后像同步一样 `LIST`
并对账（`sync::store_folders`，与 `sync::run` 第一步是同一个函数），本地的文件夹就是服务器说的那样，
随后发 `FoldersChanged`。要操作的文件夹、名字和层级都在拿到锁之后才读：拿锁之前读的可能已经被另一个
操作改了（父文件夹正在改名时新建子文件夹，会按旧名字建、建到别处去）。

- **答复丢了不当成拒绝。** 复用的连接已经断开时整个操作在新连接上重来（`pool::on_session`），而断开
  之前命令可能已经做成。重来时先 `LIST`：要建的已经在、要改的名字已经是新的、要删的已经不在，就不再
  发命令，否则第二次会被服务器拒绝，用户看到一个其实做成了的失败。
- **订阅**：`CREATE` 后 `SUBSCRIBE`，`RENAME` 把订阅从旧名移到新名，`DELETE` 后 `UNSUBSCRIBE`，方便只显示
  已订阅文件夹的其他客户端；我们自己 `LIST` 全部，不看订阅。服务器拒绝订阅不影响操作本身。
- **会话正选中着它**：重命名、删除之前，若连接正选中这个文件夹（或可能在它下面的），先 `EXAMINE INBOX`
  换掉：不是每个服务器都允许对选中的邮箱这样做；用 EXAMINE 而不是 CLOSE，CLOSE 会 EXPUNGE。

## 规则

哪些文件夹可以改由 types 的 `can_change_folder` 决定，前端用同一个函数决定菜单项（见
[架构 / 规则在引擎，措辞在前端](../architecture.md#规则在引擎措辞在前端)）：

- 有角色的不能改（INBOX、已发送、已删除、Gmail 的"所有邮件"等）：引擎按角色找它们，服务器也特殊对待。
- 下面有带角色的文件夹的也不能改（Gmail 的 `[Gmail]`）：改它会连带改那些。
- 在 IMAP 中隐藏的标签（`listed = 0`）不显示，也不能改。

在哪些文件夹里可以新建由 `can_create_in` 决定，引擎（显式给了父文件夹时）和 GUI 的菜单用同一个函数：

- 服务器说不行的不行：LIST 带 `\Noinferiors`（存在 `folders.inferiors`），或账户没有层级分隔符。服务器能
  事先告诉我们的只有这两种。
- 特殊文件夹里不行（INBOX、已发送、已删除、垃圾邮件、Gmail 的系统标签和三个位置），包含特殊文件夹的层级
  （`[Gmail]`）也不行。Dovecot、Gmail 都不给 INBOX 标 `\Noinferiors`，光看服务器 INBOX 的菜单上仍会有
  New folder，而在收件箱里建文件夹多半不是用户想要的。
- 例外是归档：`Archive/2026` 这样按年归档很常见，归档里的文件夹也是归档。
- Gmail 上于是只剩用户标签里可以建（嵌套标签）。
- 只在 INBOX 下放文件夹的服务器上，"最上层"隐含的父文件夹 INBOX 不受这条规则限制（见[新建](#新建)）。

名字：一层，去掉首尾空白；不能为空，不能含层级分隔符（父文件夹的；建在最上层时是 INBOX 的：不同的
命名空间可以有不同的分隔符）、LIST 的通配符 `*` `%` 和控制字符；与已有的
文件夹（INBOX 不分大小写）同名时 `AlreadyExists`，不发命令。非 ASCII 的名字按修改版 UTF-7 编码
（`utf7::encode`），父文件夹的部分用它在服务器上的原名，不重新编码。

## 新建

建在给定的父文件夹下，或账户的最上层。有的服务器（Courier、Cyrus）只允许在 INBOX 下建文件夹（个人
命名空间的前缀是 `INBOX.`）：账户除 INBOX 外的文件夹都在 INBOX 下时，"最上层"就是 INBOX 下面。
NAMESPACE（RFC 2342）能直接问到，但 imap-proto 不解析它的答复，需要它的服务器也少，先用这个推断。
Gmail 上新建的都是标签（对账时按账户模式定 `kind`），引擎不区分。

## 重命名

只改最后一层，留在原来的父文件夹下（不支持移到别处）。服务器的 `RENAME` 连带改它下面的文件夹
（RFC 3501 §6.3.5）。之后在对账的同一个事务里先把本地这一行和下面各行的 `remote_name`、`name` 换成
新的（`Folders::rename`），再对账：对账看到的是已有的文件夹，不会当成"旧的消失、新的出现"，于是邮件、
正文、待回放的操作（按 `folder_id` 记）、草稿的远端副本都留着。

- 服务器重命名后 UIDVALIDITY 一般不变（Dovecot 已验证），下次同步不重拉；变了就照常按新的一代处理。
- Gmail 上标签改名后 `X-GM-LABELS` 报告新名字，按 `remote_name` 对上同一个标签行，`message_labels` 不动。

## 删除

删除文件夹、它下面的文件夹和里面的邮件，在服务器上也删，不能撤销（GUI 先确认）。Gmail 上删除标签只是
从邮件上去掉它，邮件留在"所有邮件"里。

- **先回放操作队列。** 本地已经从这里移走、还没到服务器的邮件，删掉文件夹就随之丢了；所以先回放。之后
  这些文件夹里仍有待回放的操作（例如服务器拒绝打开它），或这次回放里有对这些文件夹里邮件的改动被服务器
  拒绝（被拒绝的移动撤销后邮件回到这里），就整个不删，报 `Conflict`。移进这些文件夹的未回放的移动照常由
  `forget_folder` 撤销：邮件回到原处。
- **删除期间拒绝本地改动。** 本地改动不拿同步锁，删除正等服务器答复时用户仍可能把邮件移出去：服务器删掉
  原邮件，`forget_folder` 又删掉移出去的那一行和它的操作，邮件两边都没了。所以删除在查看队列之前把这些
  文件夹记进引擎（`Engine::deleting`，结束时撤下），本地改动（`ops::change`）在写事务里检查它，改了这些
  文件夹里的邮件（所在的、移入的）或加上、去掉这个标签的，就以 `Conflict` 拒绝、整个回滚。只是显示这封邮件
  的不算（`Touched::shown`：它带着的标签、Starred）：Gmail 上删标签时给带着它的邮件加星、标已读照常，那些
  操作在"所有邮件"里做，删标签也不删邮件。不能只看操作在哪个文件夹做：移入和加标签的操作在源文件夹、
  "所有邮件"里，放过去的话，移入的邮件随文件夹删掉，标签被回放的操作重新建出来。删除查看队列也在写事务里做（写连接只有一个）：在它之前提交的
  改动它看得到，之后的都看得到标记，两者之间没有空隙。
- **按服务器现在的层级删**：先 `LIST`，删掉它和服务器上在它下面的每一个，包括别的客户端新建、本地还不
  知道的（否则父文件夹只被清空、留作 `\Noselect`，删除却报成功）；答复丢失后重来时，已经不在的自然不在
  其中。由深到浅逐个 `DELETE`（子文件夹的名字总比父文件夹长）：带子文件夹的邮箱被删除时服务器只清空它、
  留作 `\Noselect`（RFC 3501 §6.3.4）。中途被拒绝时，已删掉的照常在本地删除、对账，再返回那个拒绝。
- **本地显式删除**（`Folders::remove`，对账删除消失的文件夹也用它）：对账会把仍被邮件带着的标签留作
  `listed = 0`（Gmail 设置里隐藏的标签就是这样），所以删掉的标签要在对账之前自己删。标签删除时，显示
  这些邮件的列表（位置、其他标签、"已加星标"）也算改动，发 `MessagesChanged`：列表的行显示标签。

## 界面

- **GUI**：侧栏的右键菜单（`mailbox/folder_commands.rs`），打开时才按当时的文件夹列表决定有哪些项
  （`AccountEntry::folder_menu_entries`）。New folder（Gmail 上 New label）总是建在右键点的地方：账户地址上建在
  最上层，文件夹上建在它里面，`can_create_in` 不允许就没有这一项；可以改的（`can_change_folder`）再有 Rename、
  Delete。不另设"新建子文件夹"：同一个菜单里两种新建，哪个建在哪里有歧义。一项都没有的（INBOX、已发送，以及
  服务器没列出的层级）不弹菜单。F2 重命名
  侧栏选中的文件夹。命名的对话框（`submission::NameDialog`，与发件身份改名共用）在引擎做完之前一直开着，失败时在
  输入框下说明原因；删除先用 `confirm_danger` 确认，说明邮件的去向。菜单项的命令推迟到菜单关闭之后再执行
  （`layout::after_menu`）：否则对话框记下的"之前的焦点"是菜单，关闭后焦点落空，窗口的快捷键都不响应。GPUI Kit
  只对派发 Action 的菜单项先还焦点，带点击回调的不还；以后别的菜单打开对话框也要用它。
- **CLI**：`catmail folder add <名字> [--parent <文件夹>]`、`folder rename <文件夹> <新名字>`、
  `folder rm <文件夹>`，`--json` 输出 `{"folder": …}`（删除的是删除前的样子）。见 [CLI](cli.md)。

## 测试

- 假服务器支持 `CREATE` / `RENAME` / `DELETE` / `SUBSCRIBE` / `UNSUBSCRIBE`（Gmail 模式下改的是邮件上的
  标签），故障 `drop_after_mailbox_change` 做成之后不答复就断开。连接只记选中的邮箱名（以前按下标记，删掉一个
  邮箱会让别的连接指向另一个），邮箱被改名或删除后下一条命令得到 BYE。
- `crates/catmail-core/tests/folders.rs`：新建、重命名（邮件不重拉、待回放的操作跟着走）、删除（先回放移走的
  邮件；移出被拒绝时不删；删除期间移出被拒绝；删除期间给带着这个标签的邮件加星照常、去掉这个标签被拒绝；别的客户端新建的子文件夹一起删）、父文件夹改名途中新建子文件夹、
  按父文件夹的分隔符检查名字、拒绝的情况、INBOX 前缀的服务器、答复丢失后重来、Gmail 标签。假服务器的邮箱可以
  有自己的分隔符（`FakeMailbox::delimiter`），闸门（`ServerState::hold`）把 RENAME / DELETE 挡住，在它们进行中做别的操作，做完再放行。
- `tests/dovecot.rs` 的 `folders_are_created_renamed_and_deleted_on_dovecot` 对真实 Dovecot（用户 `folders`）
  验证同样的流程，以及重命名后 UIDVALIDITY 不变。
