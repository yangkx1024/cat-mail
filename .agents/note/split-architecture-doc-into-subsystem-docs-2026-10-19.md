# 拆分架构文档

- 日期：2026-10-19
- 类型：重构

## 背景

`docs/architecture.md` 随 M0–M4 增长到 640 多行，高层设计和实现细节混在一起，同一件事（只读同步、
按文件夹存储的邮件模型、账户删除时的取消）在几节里重复，还夹着"M0 设想、M1 改为"之类的演进过程。

## 决策

- `architecture.md` 只留分层和贯穿各子系统的设计决定（每个数据目录一个引擎、运行时桥接、事务与
  事件、邮件模型与 UIDVALIDITY、读不改服务器、发信不重复、每账户状态、安全边界、数据目录），
  子系统细节放进 `docs/architecture/`，主文档用一张表链接过去。
- 子文档按子系统分：同步、操作队列、正文与附件、草稿与发信、IMAP / SMTP 连接、存储、GUI、测试。
  连接池、认证、TLS 和连接层的严格解析被同步、下载、发信共用，单独成一篇。
- 去掉重复和演进过程，只保留结论和原因；测试的故障列表按类别整理。

## 方案

- 新增 `docs/architecture/*.md`，重写 `docs/architecture.md`。
- AGENTS.md 说明文档结构，要求实现细节写进子文档；README 里指向"GUI 一节"的链接改到 `gui.md`。
- 只改文档；检查了所有相对链接都能解析。
