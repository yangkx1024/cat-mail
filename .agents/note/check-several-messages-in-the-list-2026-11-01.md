# 邮件列表多选

- 日期：2026-11-01
- 类型：功能

## 背景

列表一次只能对一封邮件操作（读信区工具栏、悬停按钮、快捷键），清理一批邮件要一封封打开。需要像 Gmail 一样
勾选多封后一起归档、删除、移动、标记。

## 决策

- 勾选（`checked`）与选中（读信区打开的那封）分开：勾选不打开邮件，打开邮件不影响勾选，两者可同时存在。
- 头像就是勾选框：点头像切换勾选，勾选时换成 primary 底色的对钩；不另加一列复选框，行形不变。键盘上用列表里的
  X（Gmail 的键）勾选当前行，而不是让每个头像都成为焦点停留处（Tab 要走过整个列表）。
- 移走打开的邮件后打开"下一封"原来按序号：同一序号上的那一行。一起移走的勾选邮件里有排在它前面的时，同一序号
  会跳过紧挨着的那封（[A, B, C, D, E] 打开 B、勾选 A 和 B 删除，打开的是 D）。改为按身份：原来排在它后面、
  现在还在的第一行，没有就取前面最近的一行（`reselect` 拿到替换前的行）。
- 标题左边的勾选框只有"全部 / 全不"两态：gpui-kit 的 Checkbox 没有半选状态，部分勾选时显示为未勾选，再点即全选。
- 菜单项（All、Read、Unread、Flagged、Unflagged）替换已有勾选而不是追加，与 Gmail 相同；"全部"指已加载的行。
- 快捷键在有勾选时作用于勾选的邮件（Gmail 的习惯，否则按 Delete 删的是打开的那封，出人意料）；读信区工具栏的
  按钮仍只作用于它显示的那封。Labels 不做批量。
- 批量删除里要永久删除的部分一起确认一次。去向交给引擎按 `DeleteOutcome` 决定（`permanently = false`），在 Trash
  里的和要进 Trash 的一次调用；只有没有 Trash 的账户的邮件必须用 `permanently = true` 另调一次，两次之间不原子。
  根本的修法是让引擎一次调用按每封决定去向，改公共接口，记为 #190。
- 移动要求勾选的邮件同属一个账户：`move_messages` 的目标是该账户的文件夹。
- 归档 / 删除 / 移动后取消这些邮件的勾选（包括 Gmail 上仍留在列表里的），标记后保留勾选，便于继续操作。
- 悬停行原来只有已读 / 未读和删除两个按钮，统一成与读信区、勾选工具栏相同的一套：三处由同一个函数生成，
  命令用 `MessageCommand` 报告、由 `Mailbox::run` 分派，以后加减命令只改一处。行要知道能否归档，所以列表保存
  各账户的文件夹（由 `Mailbox` 设置，原来单独设置的标签名改由它得出），三处用同一个 `Applies` 判断。

## 方案

- `message_list/mod.rs`：`checked: HashSet<MessageId>`、`Check` 菜单项、`check` / `toggle_checked` / `uncheck` /
  `uncheck_all`；换来源清空，替换行时去掉已不在的。
- `message_list/rows.rs`：头像可点（`Role::CheckBox`，停止冒泡），勾选时显示对钩。
- `commands.rs`：归档、删除、移动、标记改为接受一组邮件；`selected` / `checked` / `keyed` 决定作用对象。
- `message_commands.rs`：`MessageCommand`、`Applies`（哪些命令可用、开关显示哪一面）和 `buttons`，三处工具栏共用。
- `panes.rs`：标题左边的勾选框和下拉菜单，有勾选时标题右边的工具栏；读信区工具栏也改用共用的按钮。
- `rows.rs`：悬停行的按钮改用共用的按钮，`RowCommand` 带上 `MessageCommand`。
- 测试：`mailbox/tests/checking.rs`（点头像勾选并批量标旗、归档；勾选框与菜单；快捷键作用于勾选的邮件；批量
  永久删除只确认一次；搜索结果里 Trash 中的永久删除、其余进 Trash；被别处删除的邮件不再勾选；连同前面的邮件一起删除打开的那封后打开紧接着的那封；X 勾选当前行；用勾选框和菜单勾选后列表的快捷键仍有效），`reselect` 的单元测试加了一起移走和新邮件到达的情形；悬停行的测试加上标旗和归档。`click_row` 改点发件人名字，原来的位置落在头像上。截图测试
  加了 `list-checked`、`list-check-menu`、`list-checked-reading`。
