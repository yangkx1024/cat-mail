# 预取最后也取废纸篓和垃圾邮件的正文

- 日期：2026-11-03
- 类型：功能

## 背景

后台预取（#195）不取已删除、垃圾邮件文件夹，而问服务器的搜索（#196）会搜它们。预取取完之后，正文缺失的就只剩
这两处：按正文本地搜不到，每次搜索还要为它们登录、EXAMINE、SEARCH 一遍。本机实测，除 Gmail 还在预取的"所有
邮件"外，正文缺失的全在这两处，一个账户每次搜索都是 `matched=271 found=271`（#229）。当初排除它们的原因没有
记录。

## 决策

- **排在最后，而不是继续不取。** 它们最少有人找，所以只用当天剩下的额度；Gmail 的已删除 30 天自动清空，量有限。
  垃圾邮件的正文只做清洗和索引，远程图片照常拦着，与打开一封垃圾邮件无异。
- **两次查询**：先查其他位置，一封也没有了再查已删除和垃圾邮件（`:discarded` 参数），两次都走
  `messages_prefetch` 且不用临时排序。考虑过一条查询里按"是否已删除 / 垃圾邮件"排序：排序键不在索引里，要把
  候选全读出来再排。
- 取代 #221（问服务器搜到的邮件插队下载）：那边的收益只在新账户预取完之前的几天，代价是给预取的等待循环加
  唤醒源和插队队列，评估后关掉；长期存在的那部分由这里覆盖。

## 方案

- `catmail-store/src/prefetch.rs`：`NEXT` 的过滤由排除已删除 / 垃圾邮件改成 `= :discarded`，`Prefetch::next`
  依次查两次，第一次有结果就不查第二次。
- `catmail-core/src/prefetch.rs` 模块文档、`docs/architecture/bodies.md` 相应修改。

验证：`cargo fmt`、`clippy -D warnings`、全部测试通过。store 测试加了垃圾邮件文件夹，确认有其他位置的邮件时即使
一批还有空也不带上它们（它们的邮件更新）、其他位置取完后按新到旧取它们、查询计划两次都走索引；core 集成测试
确认已删除的正文在其他之后取下、取完后服务器搜索不再发命令、额度只够一封时取的是 INBOX 最新的而不是更新的
已删除邮件，以及默认批大小下 id 更小的已删除也不会先取。变异测试：恢复不取、去掉先后、只认已删除不认垃圾
邮件、两类放进同一批，各有测试失败。
- **/simplify 整理**（复用、简化、效率、层次四个角度）：store 测试里按数量取候选的闭包与模块的 `next` 测试函数
  重复，改成给 `next` 加 `limit` 参数。没采纳：记住"其他位置已取完"以省掉第一次查询（只剩已删除 / 垃圾邮件时
  每批多走一遍它们的索引项，1 万封时每批不到 1 ms，对比 20 次网络来回）。
- **codex review 修复**（1 条，先写出不修就失败的测试）：其他位置剩下不到一批时，`next` 原先用已删除 / 垃圾
  邮件补满这一批，而 `batch()` 一批之内按文件夹 id 排序，id 更小的已删除会先取，可能用掉当天剩下的额度，普通
  邮件等到明天。改成两类不放进同一批：第一次查询有结果就不查第二次。代价是交界处少一批的量，可以忽略。测试
  `trash_waits_for_the_rest_also_within_a_batch`（Archive 排在 Trash 之后、默认批大小、额度一封）；原先为看出
  跨文件夹顺序在预算测试里设的每批 1 封随之去掉。
