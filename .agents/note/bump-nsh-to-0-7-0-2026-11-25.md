# 升级 nsh 到 0.7.0

- 日期：2026-11-25
- 类型：重构

## 背景

nsh 发布 0.7.0（自 0.6.0 起 606 个 PR）。和 0.6.1 不同，这次有一处 API 变化碰到我们，也带上了我们报的
Linux 菜单勾的修复（longbridge/nsh#2383），可以删掉对应的 ⚠️ 绕路。

## 决策

- `set_clipboard` 现在回一个 `Answer<ClipboardWrite>`（#2753，`#[must_use]`）。Agents 页复制令牌的按钮
  改成等这个回答：系统剪贴板拒绝（`Failed`）时不显示勾。Linux 和无头测试回 `Requested`（不知道系统收没收），
  照旧显示勾。没有选择直接丢掉回答：按钮显示"已复制"却没复制，正是新接口要避免的。
- 删掉 `shell/gtk.rs` 的 `MENU_CSS`、`style_menus` 和只测它的 `a_menu_check_keeps_its_shape`：nsh 0.7.0 的
  `menu_style.rs` 已给每个盒子设 `-gtk-icon-size`。
- 应用自己的 resvg 从 0.46 升到 0.48，和 nsh-core 用的一致（托盘图标原本就按"nsh-core 的 resvg"选版本），
  树里不再有两份 resvg / usvg / tiny-skia / fontdb。resvg 0.48 换成 HarfRust、read-fonts，rustybuzz 离开依赖树，
  `deny.toml` 去掉它的 advisory 忽略；ttf-parser 现在只经 nsh-core、nsh-macros 引入，改写忽略的理由。
- nsh-updater 新增无条件的 zstd（增量更新包，#2800），没有 feature 可关；许可证在白名单内，接受。
- window model v2（#2307）：桌面上引擎的根成了不显示的应用宿主，内容要放进 `window()`。真实的外壳不受影响：
  隐藏宿主的是 nsh 自己的 `run_app`，我们用的是嵌入的 `AppView`，根就是外壳开的窗口。但 nsh-testing 的
  `Headless` 在桌面系统上、没给 `EngineConfig.windows` 时把根当宿主藏起来，窗口测试全部"屏幕上什么都没有"。
  外壳的无头工具包给每个引擎一个什么都不开的 `WindowBackend`（`ShellWindows`），根照旧是窗口。没有改成
  在根里声明 `window()`：那样在 `AppView` 里 nsh 会另开一个平台窗口，和外壳自己的窗口重复。
- 输入规则现在分两步派发（#3090，先是打的字，再是规则的改动，撤销时留下打的字）。`remote_images_are_not_loaded_but_sent`
  只留最后一个 transaction，基于的状态对不上（`MismatchedTransaction`），改成按顺序都派发。
- 看过但不影响我们的破坏性变化：macOS 上指针按下
  不再给控件键盘焦点（#2783，列表的键都是窗口级的 `on_key`，不靠焦点）；RichEditor 对齐 Tiptap
  （#3089–#3099，写信只用 `EditorSession`，没调 `insertContent`）；macOS 的通知 delegate 仍是"应用有自己的
  就不装"，和 `new_mail/macos.rs` 不冲突。ROADMAP 里其余 ⚠️（通知、`wake_count`、键不分模态范围、
  sticky header、单方向滚动等）这次没有对应的上游变化，保留。

## 方案

- `Cargo.toml`、`Cargo.lock`：六个 nsh crate 到 0.7.0，resvg 到 0.48。
- `crates/catmail-gui/src/settings/agents.rs`：`copy_button` 等剪贴板的回答再显示勾。
- `crates/catmail-gui/src/shell/gtk.rs`、`ROADMAP.md`：去掉菜单勾的绕路。
- `crates/catmail-gui/src/shell/headless.rs`：`ShellWindows`；`docs/architecture/testing.md` 记下原因。
- `crates/catmail-gui/src/composer/rich.rs`：测试按顺序派发输入规则的两个 transaction。
- `deny.toml`：见上。
- `crates/catmail-gui/.claude/skills/`：换成 v0.7.0 的 skills（`3f8ecd8`）。
- 验证：macOS 上 `cargo fmt`、`clippy -D warnings`、`cargo test --workspace`、`cargo deny check` 通过；
  Linux 由 CI 的 clippy 和测试覆盖。真实窗口（`AppView` 显示根、菜单的勾、复制令牌）还要在两个平台上手动看一眼。
