# M5：图形界面——三栏、写信窗口、发件箱、设置与主题

- 日期：2026-10-20
- 类型：功能

## 背景

M4 之后 GUI 还是 M2 的最小读信窗口：只读、不能写信、阅读不标已读。M5 要把它做成能日常使用的客户端：
三栏布局、读信、写信。用户另外要求：先给出简洁易用的 UI 设计；主题可以更换，最好兼容常见终端和命令行
工具的配色，能直接导入；图标用 Heroicons。

## 决策

- **先出设计稿再实现**：Claude Design 画布"cat-mail M5 UI"六张：主窗口、回复、发件箱与离线、设置 ›
  外观（可点选主题）、导入终端配色、配色到界面角色的映射表。与用户确认的取舍：
  - **写信用独立窗口**（不放在读信区）：可以边看别的邮件边写。
  - **打开即标为已读**，设置里可关。
  - **包含转发**：引擎新增 `forward`（见 `forward-messages-2026-10-20.md`）。
  - **Drafts 只列本机草稿**：服务器 Drafts 里是本机草稿的副本，按邮件列会重复、不能编辑；代价是其他
    客户端写的草稿在 GUI 里看不到。
- **命令只有一处实现**：对邮件的命令是 `Mailbox` 的方法，工具栏、"⋯"菜单（PopupMenu 按 Action
  分派到 `Mailbox` 的焦点）和快捷键（`actions.rs`）都调用它。单键快捷键（E、Delete）只绑在列表的
  key context 里，输入框里打字不会触发。
- **一个列表四种来源**：文件夹、搜索结果、本机草稿、发件箱共用一个 `ListState`，行按身份保持选中；
  右栏按选中行的类型显示读信、草稿预览或发件箱条目。没有为草稿、发件箱各建一套列表。
- **归档 / 删除 / 移动后打开下一封**：列表先记下位置，原邮件消失后选中同一位置；服务器那边消失的邮件
  仍按 M2 的约定只清空读信区。已在 Trash 里的删除（不可恢复）才确认，其余可逆操作不弹确认框。
- **写信窗口**：
  - 一开始就是草稿（新邮件也先 `create_draft`），窗口只更新已存在的草稿，避免"第一次保存时创建"与
    并发保存建出两份；没改过的草稿关窗即删。
  - 输入停止 800 ms 自动保存；对同一草稿的引擎调用串行，发送 / 关闭 / 丢弃等正在进行的保存结束后再做，
    旧的保存不会落在发出的内容之后。考虑过用 shared future 等待前一次保存，状态机更简单、无需新依赖。
  - 草稿只能存解析得了的地址：自动保存时保留该栏上次的值；关闭时该栏有没存下的改动就提示并不关窗。
  - 后台上传草稿的去抖放在引擎（`delay-background-draft-uploads-2026-10-20.md`），不在 GUI。
- **发件箱**：客户端开启 `send_in_background`。未确认（unknown）的从不自动重发，界面给出
  "Mark as sent""Send again…"（确认可能重复）"Back to drafts"。
- **主题**：
  - 推导与导入的纯逻辑见 `import-terminal-color-schemes-2026-10-20.md`。
  - 不用 gpui-kit 的 `ThemeRegistry`：它不能替换同名主题（重新导入要覆盖），还会自己监视目录、改全局
    主题。可选主题放在自己的 `appearance::Themes` 全局，应用时写入 `Theme::light_theme` / `dark_theme`
    再 `Theme::change`。导入的主题以 gpui-kit JSON 存进配置目录的 `themes/`，与内置主题同名时加
    "(imported)"。
  - 浅色、深色各选一个主题，外观可跟随系统（主窗口观察窗口外观；Linux 上应用级外观不可靠）。
  - 导入确认放在设置对话框内部，不再叠一个对话框（设计规范：避免叠加浮层）。
  - 旗标、徽章、头像底色这些 gpui-kit 没有角色的颜色由 `theme_colors.rs` 从主题已有颜色混出，界面代码
    里没有写死的颜色；主题卡片和调色板色块是数据，例外。
- **设置存在配置目录的 `settings.json`**（`--config-dir` / `CATMAIL_CONFIG_DIR`，默认目录由 core 的
  `Config::platform_config_dir` 给出），是前端偏好，不进引擎的数据库。文字大小就是主题的 `font_size`
  （窗口的 rem），Ctrl + / − / 0 调整。设置改了由观察 `Preferences` 的回调统一应用，不靠每个调用方
  记得调用 `apply`。
- **图标**：只把用到的 Heroicons（2.2.0，MIT）放进 `assets/heroicons/` 编译进程序；gpui-kit 组件里的
  Lucide 图标在资源加载时按路径换成对应的 Heroicon，整个窗口一套图标。没有对应的（加载动画、面板开关）
  保留 gpui-kit 的。
- **账户的添加和移除移到 Settings › Accounts**，侧栏只留"New message"、位置、设置和同步。
- **侧栏只数草稿**：每个事件都重读侧栏，原先为数草稿读出全部草稿（含转发带进来的整封原文），改为
  `count_drafts`（store 的 `Drafts::count`）。搜索框停顿 200 ms 再搜索。
- 实现中发现并修复：从 `Mailbox` 的方法里打开设置时读取正被更新的 `Mailbox`（会 panic），改为传入
  client；主题卡片原是可点击的 `div`，改用 gpui-kit 的无样式 `base::Button`，得到焦点、键盘激活和
  无障碍角色；没有 Trash 的账户删除邮件时，确认后仍按"移到 Trash"请求，被引擎拒绝，改为确认后
  永久删除（测试 `deletes_for_good_without_a_trash_folder`，没有修复时失败）。
- 审查后修复（Codex review）：
  - 自动保存后地址栏仍解析不了时，关窗不再放行；关不关按各栏内容与存下的是否相同判断，不看 `dirty`。
  - 附件增删计入"引擎调用不重叠"：发送 / 关闭 / 丢弃等它们结束，刚拖进来的附件不会漏发；附件增删
    失败时，等着的发送或关闭取消，窗口留下并说明原因（发出的信不是用户想发的那封）。
  - Ctrl Q 先让写信窗口存完再退出（`composer::quit`）；GPUI 的 `quit` 不经过窗口关闭回调。
  - 地址栏用 core 新增的 `format_addresses`，带逗号的名字加引号，能被 `parse_addresses` 读回。
  - 没改动的回复点发送会照常发出（之前被当成"未改动的新草稿"删掉）。
  - 异步读完草稿后再查一次已开窗口，连点两次 Edit 只开一个。
  - 设置在后台按顺序写入（`Writer`：持锁取最新），旧快照不会后写覆盖新的。
  - 导入的主题文件不再被别的主题覆盖：新主题的文件名冲突时加序号（为序号留出长度，长名字被
    `safe_filename` 截断时序号不会被截掉而一直重试同一路径）；重新导入写回原文件并保留其中其他主题。
  - 另外发现：Ctrl Enter 在正文里会先插入换行再发送，改为在 `Composer > Input` 上直接绑定 `Send`。
  每项都有测试，去掉修复后对应测试失败。
- 整理：工具栏、右栏页面、名称与值的行、附件块放进 `layout.rs` 共用；引擎调用失败时的通知用
  `mailbox::report_failure`；"(no subject)"、名字列表、未读数规则（Sent / Junk / Trash 不显示）各只有
  一处；主题文件名用 core 的 `safe_filename`（含 Windows 保留名）；设置和主题文件共用
  `write_atomically`。

## 方案

- **按窗口和功能分目录**：原来 GUI 的文件都平铺在 `src/` 下，主窗口一个文件 1500 行。现在是
  `mailbox/`（主窗口：状态与事件、命令、侧栏、三栏、草稿 / 发件箱右栏、中栏列表、文件夹分区、
  Move to、登录表单、按主题分文件的集成测试）、`reader/`、`composer/`、`settings/`（偏好与设置
  对话框）、`theme/`（纯逻辑的调色板、推导、导入，加上应用主题的 `appearance.rs` 和 `colors.rs`），
  顶层只留启动、Action、资源和几个共用的辅助模块。超过几百行的视图按职责拆开（状态 / 生命周期 /
  渲染），单个文件不超过约 500 行；结构图见 `docs/architecture/gui.md`。
- 主窗口：`mailbox/` 加 `AccountFolders`（有角色的文件夹提前、按角色命名、Drafts 让位给本机草稿）；
  读信换新的头部（头像、收件人摘要、Details）；`main.rs` 加载设置与主题、绑定快捷键、开启后台发信。
  图标在 `assets/heroicons/`。
- 测试辅助：假 IMAP 服务器加 Archive / Drafts / Sent / Trash，新增假 SMTP 服务器。
- 文档：README（状态、图形界面用法、快捷键、配置目录）、`docs/architecture/gui.md`（结构、侧栏、读与改、
  写信窗口、发件箱、主题与设置、图标）、`docs/architecture/testing.md`、`docs/architecture.md`。

验证：`cargo fmt`、`clippy -D warnings`、全部测试通过。GUI 新增单测：设置文件读写与缺省、文字大小
步进、文件夹分区（含 `INBOX.Sent` 这种嵌套）、主题文件名与读回、Heroicon 全部嵌入且组件图标被替换。
新增 UI 集成测试：打开即已读并经队列到服务器、按 E 归档后打开下一封且服务器 Archive 收到、在写信窗口
回复并经 SMTP 发出（草稿随之删除）、未改动的新邮件关窗即删、地址写错时不关窗且草稿保留输入、设置里
切换外观和主题；原有的登录、取消、同步保持选中等测试改为通过设置进入添加账户。离屏截图检查了
三栏、读信、写信窗口、设置与 11 个内置主题；截图中看出主题卡片缩成窄条、写信字段与 From 不对齐，
已修正。真实桌面（Wayland / X11 下的多窗口、系统外观切换、文件对话框、拖放）以及 macOS / Windows
的构建没有在本地验证。
